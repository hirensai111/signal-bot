# Changelog

## 2.3.0

A second paper bot to forward-test a fixed +1.5R exit next to the unchanged strategy,
and an entry fix found in the first week of paper trading.

### Added
- **Fixed take-profit for the trend strategy.** `take_profit_r` (default 0 = off) puts a
  target at entry +/- that many R; `trail_atr = 0` turns trailing off. Research and live
  share the setting through `signals/trend.py`, so replay parity holds. The main bot's
  config is unchanged.
- **`trend_breakout_tp15` / `trend_portfolio_tp15`:** the same entries and portfolio
  rules with a 2 ATR fixed stop and a +1.5R target (docs/research.md, *Exit variants*).
- **Second paper bot (`bot-tp`, compose profile `tp`):** its own $10k account, database
  `signal_bot_tp`, state volume and control room on 127.0.0.1:8081. Enabled with
  `COMPOSE_PROFILES=tp` in `.env`. Prometheus discovers it by name; Grafana dashboards
  get a **Bot** selector (and a **Trade database** selector for the SQL panels); alerts
  are evaluated per bot; backups and `deploy/restore.sh` cover both;
  `signal_bot.ops.soak --instance` picks a bot.
- **Telegram:** `BOT_LABEL` prefixes every message; `TELEGRAM_COMMANDS=false` makes a bot
  send-only (one command listener per Telegram token).
- **Control room:** a *Target* column in *Stops and exits*.

### Fixed
- **Entries no longer miss fast breakouts.** The IOC entry was priced one tick through
  the touch, so a book that moved in the ~0.2 s before matching left it unfilled
  (`ioc_no_liquidity` on an ETH entry in the first week). It may now fill up to
  `ENTRY_LIMIT_SLIPPAGE_BPS` (10) beyond the touch, which with the 0.15% basis gate stays
  inside the research model's 30 bps entry tolerance.
- **Prices display at full precision** in the control room (DOGE showed 0.07, XRP 1.11).
- **Alert rules that aggregated across bots** (no ready symbol, stale 4h candles, market
  data age, event backlog) are now per instance, and `BotDown` only mutes its own bot's
  alerts.


## 2.2.0

Always-on paper deployment with monitoring (`docs/deployment.md`).

### Added
- **Compose stack.**
  - Loki and Grafana Alloy (searchable logs with level and subsystem labels, and symbol, order and correlation ids as structured metadata).
  - Alertmanager routing to Telegram, plus an optional dead man's switch.
  - node-exporter.
  - A read-only Grafana database role.
  - A daily `pg_dump` backup service with a staleness metric.
  - Persistent volumes for every service, and restart policies.
- **Grafana *Signal Bot: overview*** (generated by `deploy/grafana/build_overview.py`): health, paper performance from the trade tables, risk against entry limits (dashed), operations, and logs.
- **Alert rules for the paper deployment**, unit-tested with `promtool`:
  - bot down or restarted, not in paper mode;
  - warm-up failed, stale 4h data;
  - missing or unmoved stops;
  - failed reconciliation;
  - open or correlated risk beyond its entry limit, drawdown levels;
  - disk, memory, backups;
  - a Watchdog heartbeat.
- **Metrics:** build info, process (memory, restarts), per-symbol 4h readiness and last bar, decision batches, portfolio equity, peak, positions, leverage and limits, unprotected positions, reconciliation success time and failures.
- **Tooling:**
  - `python -m signal_bot.ops.preflight` checks paper-only settings; Binance REST and WebSocket reachability from the server (HTTP 451 = restricted region); clock skew; Delta products and books; database; disk; Telegram.
  - `python -m signal_bot.ops.soak` reports the soak-test criteria and server sizing figures from Prometheus.
  - `deploy/bootstrap-ubuntu.sh` sets up the server: Docker, Tailscale serve, firewall, NTP, an exact commit, generated secrets, preflight.
  - `deploy/update.sh` and `deploy/restore.sh`.
- **Paper-only lock.** `PAPER_ONLY=true` makes the bot refuse any other `EXEC_MODE`; the compose file pins both.
- **CI:** a deployment-config job (promtool, amtool, Loki, Alloy, `docker compose config`). Tests check that dashboards and alerts only reference exported metrics, and that the compose file stays private and paper-only.

### Fixed (found by running the stack in Docker)
- The bot's data volume was root-owned, so the paper broker crashed on its first state save. The image now creates the directory for its unprivileged user.
- `STRATEGY_CONFIG` did not resolve inside the installed package, so the container silently ran the 2.0 sweep. It now resolves package data, and a missing config stops startup.

## 2.1.0

Paper-trading the trend strategy as one portfolio. It is still **not validated**; see
`docs/research.md`.

### Added
- **Live 4h trend signals.**
  - `signals/trend.py` is the single implementation of the trend-breakout entry rule, used by the research backtest and by the live pipeline (`signals/trend_live.py`).
  - The pipeline decides only on completed 4h candles, from a `CandleHistory` warmed up over Binance REST.
  - It batches each bar close across symbols, so arrival order cannot change which trades are taken.
- **Replay-parity tests.**
  - Live and research decisions are bit-identical on real Binance BTCUSDT 4h bars (fixture), and after a 1000-bar REST warm-up.
  - A full-stack replay (pipeline, governor, engine, simulated venue, trailing stops, outcomes) takes the same 28 trades as the backtest.
- **Trailing stops end to end** (`execution/trailing.py`). Stepped mode is the default, and the researched exit: after every completed bar the exchange-resident stop moves to the research rule's level, never looser.
  - Reconciliation re-derives trailing stops after a restart: looser venue stops are amended, tighter ones adopted, and a stop already through the market exits.
  - Time stops at the strategy's last bar.
  - Recovery stops use the trailed level.
  - Exits are recorded as `trail_hit` and `time_stop`.
- **Native trailing option** (`TRAIL_MODE=native`) through Delta's `bracket_trail_amount`, with `DELTA_TRAIL_AMOUNT_SIGN`.
- `python -m signal_bot.delta.trail_check`: a testnet-only probe that measures Delta's trailing-stop sign, its behaviour, and stop editing.
- **Venue support.** `ExchangeAdapter.amend_stop` and `account_equity`.
  - Delta: stop edits via `PUT /v2/orders`; stop and trail read from the resting stop order; equity = wallet balance + unrealised PnL; position size limits.
  - The simulated venue and paper broker support amendment and continuous native trails, persisted across restarts.
- **Portfolio rules** (`risk/portfolio.py`), shared by live trading and research.
  - At each bar close they rank simultaneous entries and size them on marked-to-market shared equity in whole Delta contracts, capped by position limits.
  - Limits: positions, total open risk to current stops, correlation-adjusted risk, gross leverage, entries per bar, and a margin buffer.
  - Drawdown: risk is halved at 10%; at 20% the `portfolio_drawdown` breaker stops new entries.
  - The governor re-checks just before submission.
- **Portfolio research.**
  - `research/portfolio.py` replays all symbols on one timeline with the unchanged fill model, Delta contract specs and listing dates (`research/delta_universe.json`).
  - `scripts/research_portfolio.py` runs it.
  - `trend_portfolio.toml` is the frozen signal plus a priori portfolio limits, and is the new default `STRATEGY_CONFIG`.
- **Control room:** stops and exits, portfolio risk, and trend signal panels.
- **Metrics:** trailing-stop updates, time stops, trend decisions, portfolio open/correlated risk and drawdown.
- **Schema upgrade.** Additive and idempotent, run at startup (`db/migrate.py`).

### Changed
- **Default strategy.** `STRATEGY_CONFIG` defaults to the trend portfolio. The 2.0 sweep still runs with `liquidity_sweep.toml`.
- **Production market data by default.** `BINANCE_TESTNET` defaults to `false`. It only selects market data, and the testnet feed is synthetic. Trend mode refuses to start on it.
- **Stop-market brackets.** Delta bracket stops are stop-market orders (no `bracket_stop_loss_limit_price`), as the fill model assumes.
- **Trend-mode governor limits.** They are derived from the portfolio rules: 6 positions, -6R/day, 18 trades/day, 15 consecutive losses. The 1R-per-open-position projection is replaced by the portfolio's open-risk cap. Explicitly set, stricter settings still apply, and `RISK_PCT_PER_TRADE` and `MAX_CONCURRENT_POSITIONS` cap the portfolio.
- **Corrected docs.** The research trail is stepped (once per completed bar), not Delta's continuous `bracket_trail_amount`.

### Research
- **Candidates.** `trend_breakout` (4h Donchian, EMA200 and volume filters, trailing stop) and `liquidity_sweep_v2`. Pre-registered holdout testing with `scripts/research_dev.py` and `scripts/research_holdout.py`.
- **Trend breakout 0.2.0, per coin:** +0.10R per trade across 11 coins in the holdout year (not significant).
- **As one portfolio** (look 3 at the holdout year): +3.4% with a -16.4% drawdown, against +19.6% claimed by summing the per-coin backtests. Not validated.

## 2.0.1

### Fixed (Delta Exchange India API alignment, per docs.delta.exchange)
- Private WebSocket authentication uses `key-auth` (the old `auth` method was removed on 31 Oct 2026) and waits for the auth response before subscribing; failures report Delta's status (for example `invalid_signature`, `ip_not_whitelisted`).
- Testnet private socket is the documented `wss://socket-ind.testnet.deltaex.org`.
- Subscribes to the documented private channels `orders`, `positions` and `user_trades` with explicit symbols; enables the server heartbeat and reconnects after 35 s of silence.
- Fill parsing handles both `user_trades` and `v2/user_trades`; `"c"` (client order id) is no longer read as the commission. Fills that don't say whether they opened or closed a trade are classified against the local order's side.
- Snapshot messages (`action: "snapshot"`) are normalised row by row.
- Products: follows the cursor pagination and maps only live perpetual futures; symbols Delta doesn't list are reported and refused instead of aborting startup.
- Delta cancels include the product id.

### Added
- `python -m signal_bot.delta.client --ws-check`: a read-only socket probe (authenticate, subscribe, print messages; places no orders).

## 2.0.0

Signal Bot 2.0: from a signal bot to a fault-tolerant trading platform.

### Fixed (from the code review)
- The startup path used an always-approve governor; the real `RiskGovernor` now gates every submission and fails closed.
- The execution engine and outcome monitor shared one `asyncio.Queue` and could steal each other's exchange events; each consumer now has its own subscription.
- The HTF scanner and microstructure engine shared the closed-candle queue and discarded each other's candles; each now has an independent, interval-filtered subscription.
- A placement timeout marked the order cancelled; it is now `submission_unknown` and resolved by client-id lookup, never resubmitted.
- Position sizing ignored price (`notional / contract_value`); it is now `notional / (contract_value × price)`.
- The reconciler marked orders with an unknown exchange state as cancelled; they now stay blocked until resolved.
- Live 1h/4h candles were never subscribed, so HTF levels froze after backfill.
- The still-forming backfill candle was stored and forwarded as closed.
- Backfilled (historical) candles could generate live signals; candles are now gated on freshness.
- `agg_trades` had no `(symbol, ts)` index, so the microstructure query did a full scan on every candle.
- A Binance outage crashed the whole process, including stop management.
- `db/connection.py` imported a second copy of the settings module.

### Added
- Event contract, fan-out bus, PostgreSQL event journal with checkpoints and replay.
- Persistent order state machine (`orders`, `order_transitions`, `fills`).
- Exchange adapter interface; Delta adapter with an error taxonomy and timeouts.
- Protective-order verification and recovery (standalone stop, then flatten).
- Risk circuit breakers, worst-case daily loss budget, submission-time trade counting, UTC day roll-over.
- Fault-injecting simulated venue; paper broker on live order books.
- Nine end-to-end failure scenarios, run on SQLite and PostgreSQL.
- Research: deterministic fill model, exhaustion-reversion and regime-filter strategies, IS/OOS, walk-forward, cost sensitivity, random baselines, versioned reports, session reports.
- Observability: JSON logs, Prometheus metrics and alerts, Grafana dashboard, control room, authenticated halt/resume with audit trail.
- CI (lint, format, multi-Python tests, PostgreSQL, replay, pip-audit, build), release workflow, Dependabot, Docker Compose stack.

### Changed
- `EXEC_MODE=dry_run` (instant fills at the signal price) is replaced by `paper`; `dry_run` remains an alias.
- Production trading requires `LIVE_TRADING_ACKNOWLEDGED=true`.
- The package is installable (`pip install -e .`) and lives in `signal_bot/`.
